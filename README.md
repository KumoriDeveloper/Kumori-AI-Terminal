# Ryoku AI Terminal

AI-ассистент для терминала на **CachyOS / Arch Linux** с **Fish**, Hyprland и Wayland.
Понимает запросы на русском, работает в обычном терминале, показывает состояние
системы и **не выполняет команды без вашего подтверждения**.

```
$ ai почему медленный интернет
$ ai найди процессы, которые едят память
$ ai объясни ошибку из journalctl
$ ai --docker
```

> Бесплатные тарифы Groq и OpenRouter ограничены квотами.
> Платная подписка не требуется, но и гарантии безлимитной работы нет.
> Приложение не содержит «встроенной» модели: нужен хотя бы один API-ключ.

---

## Возможности

- **Структурированные планы.** Диагностические команды и системные действия
  разбираются отдельно; действия проверяются по Pydantic-схеме и allowlist.
- **Два провайдера с резервом.** Groq → OpenRouter. При ошибке подключения,
  лимите квоты или недоступности модели выполняется переход к резервному
  провайдеру или другой проверенной модели.
- **Автовыбор модели.** Список моделей запрашивается у официальных API
  провайдеров; ничего не выдумывается. Модель можно выбрать вручную.
- **Локальная диагностика без ИИ.** Сеть, система, процессы, диски/Btrfs,
  systemd, Docker и Steam — работают даже без ключей.
- **Безопасное выполнение.** Каждая команда показывается с описанием
  последствий и требует подтверждения. Для sudo — отдельное подтверждение.
- **История в SQLite.** Хранится локально, с маскированием секретов.
- **Русский интерфейс.** Rich-панели, таблицы, Markdown, понятные ошибки.
- **Низкие требования.** Python 3.10+, без локальной LLM и без GPU. Вся
  тяжёлая работа выполняется API-провайдером, поэтому подойдут и слабые
  машины (например, ноутбук с 11 GB RAM и дискретной GPU 2 GB).

---

## Требования

- CachyOS, Arch Linux или совместимый дистрибутив (Manjaro, EndeavourOS).
- Python **3.10+** и модуль `venv`.
- Fish (для команды `ai`).
- Утилиты диагностики по желанию: `iproute2`, `procps-ng`, `bind`, `btrfs-progs`,
  `lm_sensors`, `docker`, `nvidia-utils`. Отсутствующие утилиты не ломают
  приложение — `ai doctor` покажет, чего не хватает.
- Интернет и API-ключ хотя бы одного провайдера для AI-запросов.

## Установка

```fish
cd /путь/к/ryoku-ai-terminal
./scripts/install.sh
```

Что делает установщик:

1. Проверяет, что система похожа на Arch/CachyOS (обойти можно только
   осознанно: `--force`).
2. Создаёт отдельное виртуальное окружение
   `~/.local/share/ryoku-ai/venv` и ставит зависимости **только туда**.
   Системный Python и пакеты Arch не изменяются.
3. Копирует пакет `ryoku_ai` в venv, создаёт launcher
   `~/.local/bin/ryoku-ai`.
4. Устанавливает Fish-функцию `~/.config/fish/functions/ai.fish` и
   `~/.config/fish/conf.d/ryoku-ai.fish` (добавляет `~/.local/bin` в `PATH`).
5. Проверяет импорт установленного пакета и печатает версию.

Опции установщика:

| Опция               | Назначение                                                    |
| ------------------- | ------------------------------------------------------------- |
| `--bin-dir DIR`     | каталог launcher-а (по умолчанию `~/.local/bin`)              |
| `--prefix DIR`      | то же, но как `DIR/bin`                                       |
| `--venv DIR`        | каталог venv                                                  |
| `--fish-config DIR` | каталог Fish (`~/.config/fish`)                               |
| `--no-fish`         | не устанавливать Fish-функцию                                 |
| `--offline`         | не обращаться к PyPI, проверить уже установленные зависимости |
| `--force`           | продолжить на не-Arch системе / перезаписать чужой `ai.fish`  |

Открыть новый терминал (или `exec fish`) и проверить:

```fish
ryoku-ai --version
ai --version
```

### Первая настройка

После установки откройте новый Fish-терминал (или выполните `exec fish`), затем:

```fish
ryoku-ai --version
ryoku-ai setup
ryoku-ai --models
ai почему медленный интернет
```

Мастер предложит ввести ключи Groq и OpenRouter скрытым вводом и проверит
каждый через API. Не добавляйте ключи в командную строку. По умолчанию первым
используется Groq, OpenRouter — резерв; `--models` показывает доступность и
модели, полученные от каждого настроенного провайдера.

Ключи можно также передать через `GROQ_API_KEY` и `OPENROUTER_API_KEY` в
окружении. В этом случае мастер настройки не обязателен.

Если команда `ryoku-ai` не найдена, откройте новый терминал и проверьте, что
`~/.local/bin` находится в `PATH`. В оболочке Fish установщик добавляет путь
автоматически. Без Fish используйте `ryoku-ai`; короткая команда `ai`
устанавливается только как функция Fish.

Мастер предлагает ключи этих провайдеров:

| Провайдер  | Где получить ключ               | Примечание                            |
| ---------- | ------------------------------- | ------------------------------------- |
| Groq       | <https://console.groq.com/keys> | быстрый, бесплатные квоты             |
| OpenRouter | <https://openrouter.ai/keys>    | бесплатные модели с суффиксом `:free` |

Ключи сохраняются **только локально**:

```
~/.config/ryoku-ai/credentials.env   (chmod 600)
```

Ключи не попадают в историю, логи, аргументы командной строки или Git
(см. `.gitignore`). Ключ, который не прошёл проверку, не сохраняется.

Если ключей нет, работают локальные режимы: `ai --network`, `ai --system`,
`ai --processes`, `ai --storage`, `ai --services`, `ai --docker`,
`ai doctor`.

## Использование

### Запрос к AI

```fish
ai почему медленный интернет
ai проверь, не перегревается ли ноутбук
ai что занимает место на диске
ai --explain "journalctl -b -p err"
```

Приложение может предложить до трёх команд (лимит задаётся `max_commands`).
Каждая команда — это **argv-массив без shell-строки**. Перед выполнением
показываются:

- сама команда;
- описание действия;
- последствия;
- уровень риска.

Выбор: `[1] Выполнить`, `[2] Изменить`, `[3] Отмена`. По умолчанию —
отмена. Если терминал не интерактивный, команды не выполняются.

Изменяющие операции показываются отдельно как `RYOKU AI — ACTION PLAN`.
Каждое действие подтверждается отдельно: Enter — подтвердить, `2` — изменить
в пределах разрешённых операций, `3` — пропустить, `4` — отменить весь план.
Операции с root требуют ещё одного отдельного подтверждения sudo.

Для `/tmp`, `/var/tmp` и `~/.cache` размер сначала измеряется встроенным
непривилегированным Python-инспектором. Он не переходит по symlink, ограничивает
обход и сохраняет доступный результат при частичных ошибках прав. Такой результат
помечается `PARTIAL RESULT`; нулевой доступный размер не означает пустой каталог.
Очистка временных файлов выполняется только по правилам `systemd-tmpfiles`.
Кеш pacman анализируется через `paccache`, а
очистка оставляет три версии пакетов. `pacman -Scc` не запускается. Пользовательский
`~/.cache` можно только анализировать, но не удалять. Журналы systemd сначала
показывают занимаемый объём; ограничение архивных журналов — отдельное действие
с высоким уровнем риска и отдельным подтверждением. Используемые временные файлы
и кеши блокируют соответствующую очистку.

`--no-exec` — только показать план, ничего не запускать:

```fish
ai --no-exec проверь сеть
```

### Интерактивный чат

```fish
ai --chat
```

Команды `/exit` (или `/quit`), `/help` и `/clear` доступны внутри чата.
История диалога ограничена и хранится локально.

### Диагностика без ИИ

```fish
ai --network      # интерфейсы, адреса, маршруты, DNS, сокеты
ai --system       # CPU, RAM, диски, температура, GPU
ai --processes    # процессы и потребители ресурсов
ai --storage      # диски, Btrfs, крупные каталоги
ai --services     # systemd, ошибки журнала
ai --docker       # Docker, контейнеры, Steam
```

### История и модели

```fish
ai --history                 # последние диалоги
ai --history-show 12         # диалог по ID
ai --history-clear           # очистить (с подтверждением)
ai --models                  # модели всех настроенных провайдеров
ai --models --provider groq
ai --config                  # конфигурация и пути
```

`ai --history-show ID` также раскрывает сохранённый полный ограниченный вывод
stdout/stderr; обычный экран сворачивает длинные stderr-предупреждения.

### Подкоманды

```fish
ryoku-ai setup
ryoku-ai models [--provider groq|openrouter]
ryoku-ai history [--limit N] [--show ID] [--clear] [--yes]
ryoku-ai config [--init]
ryoku-ai doctor
```

`ryoku-ai config --init` создаёт `~/.config/ryoku-ai/config.toml` с
комментариями и правами 600, не перезаписывая существующий файл.

### Выбор провайдера и модели

```fish
ai --provider openrouter "почему нет DNS"
ai --provider groq --model <точный-id-модели> "проверь сеть"
```

Порядок по умолчанию: `groq → openrouter`. При ошибке авторизации
провайдер временно исключается; при лимите квоты — конкретная модель или
провайдер ставятся на паузу, затем запрос повторяется у следующего кандидата.
Паузы действуют только в текущем процессе.

## Конфигурация

Файл: `~/.config/ryoku-ai/config.toml` (создаётся `ryoku-ai config --init`).

```toml
language = "ru"                 # пока поддерживается только ru
theme = "ryoku"                 # ryoku | mono | accessible (без цвета)

provider = "auto"               # auto | groq | openrouter
provider_order = ["groq", "openrouter"]
fallback_enabled = true
model = ""                      # общая модель, пусто = авто
request_timeout = 60.0          # 5..300 секунд
connect_timeout = 10.0          # 2..60 секунд
max_tokens = 2048               # 128..8192
temperature = 0.2               # 0..1.5

command_timeout = 20.0          # 1..120 секунд
max_output_chars = 12000        # лимит вывода команды
ai_output_chars = 6000          # сколько вывода отправлять модели
max_commands = 3                # 0..5 команд на запрос
confirm_commands = true         # всегда true, изменить нельзя
allow_sudo = true               # sudo только с отдельным подтверждением

history_enabled = true
history_context_messages = 6
max_history = 1000
analyze_results = true          # AI анализирует вывод выполненных команд
auto_context = true             # короткий контекст системы в запросе

[provider_models]
# groq = "точный-id-модели"
# openrouter = "точный-id-модели:free"
```

Пути можно переопределить переменными окружения (используется в тестах):

```
RYOKU_AI_CONFIG_DIR
RYOKU_AI_CONFIG_FILE
RYOKU_AI_CREDENTIALS
RYOKU_AI_STATE_DIR
RYOKU_AI_HISTORY_DB
```

Ключи также читаются из переменных `GROQ_API_KEY` и `OPENROUTER_API_KEY`. Переменные окружения имеют
приоритет над файлом `credentials.env`; ключи из окружения не записываются
на диск автоматически.

## Модель безопасности

Ключевой принцип: **AI предлагает — пользователь решает**. Автоматического
исполнения нет.

1. **Структурированный вывод.** Модель возвращает JSON: read-only команды в
   `commands`, изменения — в типизированном `actions`. Свободный текст никогда
   не исполняется.
2. **Белый список.** Диагностические команды ограничены read-only утилитами
   (`ss`, `ip`, `ping`, `dig`, `journalctl`, `systemctl`, `ps`, `df`, `du`,
   `lsblk`, `btrfs`, `sensors`, `nvidia-smi`, `docker`, `pacman -Q…`,
   `lspci`, `lsusb`, `uname`, `uptime`, `stat`, `ls`, `sysctl` и т. п.).
   `rm`, `mv`, `chmod`, `pacman -S`, `systemctl restart`, `kill`, `curl`,
   `bash`, `sh`, `python`, `eval`, `xargs` и подобные запрещены. Изменения
   ограничены фиксированным allowlist безопасных операций очистки.
3. **Никакого shell.** Запрещены `shell=True`, `sh -c`, `bash -c`, цепочки
   `;`, `&&`, `||`, pipe, перенаправления и подстановки `$()`. Запрещены
   глобы. Бинарник должен находиться в системном каталоге.
4. **Проверка аргументов.** Для каждой утилиты разрешены только конкретные
   флаги и форматы значений; проверяются пути и имена unit/контейнеров.
5. **Защита секретов.** Чтение `~/.ssh`, `~/.gnupg`, `~/.aws`, keyring,
   `credentials.env`, `history.db`, `/proc/*/environ` и похожих путей
   блокируется.
6. **Подтверждение.** Команда не запускается без явного подтверждения; каждое
   cleanup-действие подтверждается отдельно. При
   редактировании команда проверяется заново по тем же правилам. До
   подтверждения фиксируется digest команды, а перед запуском он сверяется
   с повторной проверкой.
7. **Sudo отдельно.** `sudo` не входит в argv. Используется только
   `sudo -n -- <команда>` после второго подтверждения. Пароль не
   запрашивается и приложению не передаётся; если sudo требует пароль,
   команда просто не выполнится.
8. **Лимиты.** Таймаут команды, ограничение размера вывода, число команд,
   отсутствие интерактивного ввода (`stdin=/dev/null`).
9. **Маскирование.** Перед отправкой модели и записью в SQLite вывод
   очищается от типовых ключей, токенов, паролей и приватных ключей.
10. **Локальные ключи.** `credentials.env` создаётся с правами 600, каталог — 700. `ai doctor` предупреждает о неверных правах.

Ограничения, о которых важно помнить:

- это **не песочница**: разрешённые read-only команды всё равно видят
  систему, а их вывод может содержать чувствительные данные;
- приложение не устанавливает пакеты, не меняет конфигурацию и не
  перезапускает службы; оно может выполнять только перечисленные выше
  операции очистки после отдельного подтверждения;
- качество советов зависит от модели и квот;
- бесплатные тарифы могут меняться и ограничивать модели.

## Как это устроено

```
src/ryoku_ai/
  cli.py                 Typer + Rich: интерфейс, сценарии, подтверждения
  config.py              config.toml, credentials.env, атомарная запись
  context.py             короткий локальный контекст без секретов
  redaction.py           маскирование токенов и паролей
  conversation.py        сессия диалога и окно контекста
  ai/                    провайдеры Groq/OpenRouter, router с fallback/cooldown
  execution/             planner, validator, approval, executor
  system/temp_inspector.py  ограниченный read-only обход каталогов без symlink
  storage/               SQLite: диалоги, сообщения, команды, диагностика
  system/                локальные отчёты без ИИ
fish/functions/ai.fish   обёртка `ai` → `ryoku-ai`
scripts/install.sh       установка в отдельный venv
scripts/uninstall.sh     удаление с сохранением данных по умолчанию
tests/                   pytest + httpx.MockTransport
```

Стек: Python 3, Typer, Rich, HTTPX, Pydantic, SQLite (stdlib), pytest, Ruff.
Провайдеры используют официальные HTTP API:

- Groq — `https://api.groq.com/openai/v1` (OpenAI-совместимый);
- OpenRouter — `https://openrouter.ai/api/v1` (OpenAI-совместимый);
  Модели ищутся через `/models` соответствующего провайдера перед использованием.
  OpenRouter ограничен моделями с официальной пометкой `:free`. Если провайдер
  недоступен, используется резерв или показывается ошибка, а не выдуманное имя.

## Разработка и тесты

```fish
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m ryoku_ai --version
.venv/bin/python -m ryoku_ai setup
.venv/bin/python -m ryoku_ai --models
.venv/bin/python -m ryoku_ai "почему медленный интернет"
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check .
```

Тесты не обращаются к реальным API: HTTP замокан через
`httpx.MockTransport`. Проверяются роутер и fallback, ошибки провайдеров,
лимиты и таймауты, конфигурация и права файлов, SQLite и маскирование,
валидация argv и запрет опасных команд, подтверждение и sudo, исполнение,
таймауты и лимиты вывода, структурированные cleanup-планы и per-action approval.
Все изменяющие cleanup-вызовы изолированы mocked runner-ом: реальная очистка во
время тестирования не выполняется. Проверяются также Fish-интеграция и CLI.

Установка в изолированные каталоги (например, для проверки):

```fish
./scripts/install.sh --offline --venv /tmp/ryoku/venv \
    --bin-dir /tmp/ryoku/bin --fish-config /tmp/ryoku/fish
```

## Удаление

```fish
./scripts/uninstall.sh            # спросит подтверждение
./scripts/uninstall.sh --yes      # без вопросов
```

По умолчанию удаляются launcher, venv и **только те** Fish-файлы, которые
содержат маркер установщика. Сохраняются:

```
~/.config/ryoku-ai/config.toml
~/.config/ryoku-ai/credentials.env
~/.local/state/ryoku-ai/history.db
```

Полное удаление вместе с ключами и историей:

```fish
./scripts/uninstall.sh --purge --yes
```

Чужие файлы не удаляются без `--force`. Системный Python и пакеты Arch
не затрагиваются.

## Диагностика проблем

```fish
ryoku-ai doctor        # Python, Fish, утилиты, права ключей, провайдеры
ai --config            # пути, режимы, статистика истории
ai --models            # доступные модели и ошибки провайдеров
```

Типичные ситуации:

- **«Не настроен ни один AI-провайдер»** — выполните `ryoku-ai setup`.
- **401/403** — ключ неверный или отозван; повторите `ryoku-ai setup`.
- **429** — исчерпана бесплатная квота; подождите или смените провайдера
  (`--provider`). Приложение само попробует резерв.
- **Команда заблокирована** — она не входит в read-only белый список.
  Это ожидаемое поведение, а не ошибка.
- **`sudo -n` не сработал** — для sudo нужен пароль. Выполните команду
  вручную; приложение намеренно не собирает пароли.
- **`ai: команда ryoku-ai не найдена`** — откройте новый терминал или
  проверьте `~/.config/fish/conf.d/ryoku-ai.fish`.
